# Resolución de Problemas — Mejorar o Iterar (teoria)

> Tema del MAPA: `mejorar_o_iterar`. Depende de: a determinar (ver dependencias.md).

## Tipo de teoría (si esto se carga al sistema)

**Presentación** — El proceso de iterar permite perfeccionar soluciones mediante ciclos sucesivos de evaluación y ajuste.

---

## 1. ¿Qué significa iterar?

Iterar es repetir un ciclo de trabajo para mejorar una solución existente, no para reemplazarla. Cuando se implementa una primera versión que cumple con el objetivo básico pero deja espacio para optimización, la iteración permite identificar fallos menores, ajustar parámetros y acercarse a un resultado más eficiente o completo. No es un proceso lineal: cada ciclo puede generar nuevas observaciones que requieren otro ciclo de trabajo.

## 2. Evaluación continua como motor de cambio

La evaluación no es un paso único, sino una acción constante. Incluso si una solución cumple con los requisitos mínimos establecidos al inicio del problema, su análisis puede revelar ineficiencias o errores que no se consideraron en la primera etapa. Por ejemplo: un programa que resuelve un cálculo matemático básico podría tener errores de redondeo que solo aparecen en casos extremos. Detectar estos problemas implica reiniciar el proceso, no finalizarlo.

Este tipo de retroalimentación (feedback) es clave para decidir si se debe mejorar o abandonar una solución. La iteración no presupone que la primera versión sea "mala", sino que reconoce que las condiciones del problema pueden cambiar o que existen variables no exploradas aún.

## 3. Componentes de un ciclo de mejora

Cada iteración sigue una secuencia lógica: primero se analiza el problema con la solución actual, luego se identifican los puntos débiles y se proponen ajustes. Estos cambios se implementan, y finalmente se verifica si el nuevo resultado es más cercano al objetivo. Si no lo es, se repite el ciclo.

Este proceso no siempre avanza de forma lineal: un ajuste en una etapa puede afectar otras partes del sistema resuelto. Por ejemplo, corregir un error de cálculo en un software podría generar incompatibilidades con módulos previamente funcionales. En ese caso, el ciclo vuelve a comenzar desde el análisis, integrando la nueva información.

## 4. Cuándo detenerse y cuándo seguir

La decisión de iterar no depende solo del éxito parcial de una solución, sino de criterios definidos desde el inicio: ¿qué nivel de precisión se requiere? ¿cuántos recursos están disponibles para ajustes? En proyectos con plazos estrictos, puede ser más eficiente aceptar un resultado "suficiente" que perseguir la perfección. Sin embargo, en contextos como investigación o desarrollo tecnológico, la iteración suele ser obligatoria por naturaleza.
